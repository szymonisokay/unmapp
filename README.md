# unmapp

An [Expo](https://expo.dev) app (SDK 57) built with [expo-router](https://docs.expo.dev/router/introduction). **iOS is the only target for now.** The codebase stays cross-platform because Expo makes that free, but web is out of scope and nothing is checked against it.

## Requirements

- Node.js 20+
- Xcode with an iOS Simulator

## Get started

The app uses Mapbox, which is native code, so **it cannot run in Expo Go** — it
needs a development build compiled onto the Simulator. Setting that up is a
one-off; after it, the daily loop is the same as before.

```bash
npm install
```

Copy `.env.example` to `.env.local` and fill in two values: the Mapbox public
token from [your Mapbox account](https://account.mapbox.com/access-tokens/), and
the published style URL (see [The map](#the-map) below). `.env.local` is
gitignored; `.env.example` documents what belongs in it.

Without the token the map is a blank grey rectangle. Without the style URL it
falls back to a stock Mapbox style, so it works but does not look like the
design. Both cases log a warning in development. Environment variables are read
when Metro starts, so **restart Metro after editing `.env.local`** — Fast Refresh
will not pick the change up.

```bash
npx expo prebuild --clean --platform ios
```

That generates the `ios/` project from `app.config.ts`. It is safe to re-run at
any time — the directory is regenerated from scratch, which is why nothing in it
may ever be hand-edited.

```bash
npx expo run:ios
```

That compiles the app and installs it on the Simulator — a full Xcode build, so
the first one takes minutes. Note it is `expo run:ios`, not `npm run ios`: the
npm script is `expo start --ios`, which only starts Metro and cannot build
native code.

Afterwards `npm run ios` is the daily command again, and leaving Metro running
is the usual workflow — one long-lived instance that everything attaches to,
rather than restarting it per change.

Rebuild (`prebuild` + `npm run ios`) only when native configuration changes: a
new native package, a changed config plugin, or a new permission string. Pure
JavaScript and TypeScript changes arrive over Fast Refresh.

The `android` and `web` scripts still exist in `package.json` and will run, but
neither is a supported target: nothing is designed, checked, or fixed against
them, and the map in particular is only set up for iOS.

## Project layout

```text
src/app/           expo-router routes — file name is the URL path
  _layout.tsx      root layout (Stack, no headers)
  (tabs)/          route group — the parentheses keep it out of the URL
    _layout.tsx    the four-tab bar
    index.tsx      "/" — the map screen
    odkryj.tsx     misje.tsx  profil.tsx  — placeholders
src/components/    shared UI primitives (Text, Card, Chip, PillButton, ...)
  map/             the map view and the two cards floating over it
  navigation/      the tab bar icons
src/design/        colour, spacing, radius, and type tokens; font loading
src/domain/        app vocabulary (Place, Discovery, Mission) and pure helpers
src/data/          the discovery repository, its in-memory impl, and data hooks
src/i18n/          i18next setup; language comes from the device
src/location/      permission and position, as a hook
messages/          translated copy — pl.json and en.json
map-style/         the Mapbox style document, uploaded to Studio by hand
assets/images/     app icons, splash, and image assets
assets/expo.icon/  iOS icon composition source
app.config.ts      Expo config: name, scheme, icons, plugins, experiments
.env.example       the environment variables the app needs; copy to .env.local
tsconfig.json      strict TS; "@/*" -> ./src/*, "@/assets/*" -> ./assets/*,
                   "@/messages/*" -> ./messages/*
```

There is no `ios/` or `android/` directory in git — native projects are generated by
`npx expo prebuild` and are gitignored. Change native config in `app.config.ts`, not
in generated folders; anything edited inside `ios/` is lost on the next prebuild.

`app.config.ts` is TypeScript rather than JSON because it reads secrets from the
environment. Keeping the Mapbox download token out of git is the reason — see the
comments at the top of the file.

## Language

The app speaks Polish and English. Nothing the user reads is written in a component:
copy lives in `messages/pl.json` and `messages/en.json` and is read with the `t()`
function from [react-i18next](https://react.i18next.com).

```tsx
import { useTranslation } from 'react-i18next';

const { t } = useTranslation();
return <Text variant="display">{t('home.headline')}</Text>;
```

`messages/pl.json` is the source of truth for the key set — TypeScript derives the
allowed keys from it, so `t('home.headlin')` fails `npx tsc --noEmit`. Add a key
there first, then translate it in `messages/en.json`; a key missing from English
falls back to the Polish text at runtime rather than showing the raw key.

The language comes from the device (`expo-localization`) and there is no picker:
a phone set to Polish gets Polish, anything else gets English. iOS restarts the app
when its language changes, so there is nothing to re-read at runtime and nothing is
stored on disk.

Counts use i18next plurals — `discovery.count` in `messages/pl.json` shows the four
Polish forms (`_one`, `_few`, `_many`, `_other`). These need `Intl.PluralRules`,
which Hermes does not ship, so `src/i18n/index.ts` imports the `intl-pluralrules`
polyfill first. Without it every count silently renders the `_other` form.

To see the English copy on a Polish simulator, change the simulator's language in
Settings, or temporarily pass `lng: 'en'` to `init()` in `src/i18n/index.ts`.

## The map

The home screen is a [Mapbox](https://rnmapbox.github.io/docs/install) map with two
cards floating over it. Three things are worth knowing before touching it.

**Coordinate order.** Mapbox takes `[longitude, latitude]`; `expo-location` returns
`{ latitude, longitude }`. The flip happens in one place, `DiscoveryMap`, which takes
the named-object form. Swapping them puts Katowice in the Indian Ocean and nothing
warns you.

**The style is a URL, and the style itself is a file.** The cream cartography from
`app-design/v1/04-mapa.png` lives as a Mapbox Style Specification document in
`map-style/unmapp-cream.json`. The URL of its published copy lives in `.env.local`
as `EXPO_PUBLIC_MAPBOX_STYLE_URL`, so pointing the app at a different style — a
draft, a dark variant — is a config change rather than a commit.

To change how the map looks: upload that file in Mapbox Studio (New style → upload),
publish, and put the resulting `mapbox://styles/<username>/<id>` in `.env.local`.
Styles are hosted by Mapbox, so later edits are published from Studio and reach the
app without a rebuild or a code change.

One catch: publishing under an **unchanged** URL does not reach an app that has
already run. The Mapbox SDK caches the style on disk, and relaunching is not enough —
reinstall the app, or erase the simulator, to see the new version.

Keep the two in step. If a style is edited in Studio, export it back over
`map-style/unmapp-cream.json`, otherwise the repository stops describing what users
actually see. Validate before uploading:

```bash
npx -y -p @mapbox/mapbox-gl-style-spec gl-style-validate map-style/unmapp-cream.json
```

Labels are set in Poppins, the same sans the app uses. Mapbox hosts it, so nothing has
to be uploaded. The weights follow `src/design/tokens.ts` rather than map convention:
districts use Poppins Regular to match the `eyebrow` style they imitate, cities use
Poppins SemiBold to match `label`. Custom *icons* are still not carried inside the
style document — those would have to be added in Studio by hand.

The style carries four label layers: cities and districts from `place_label`, street
names from the `road` layer, and landmarks from `poi_label`. Building names are not in
the `building` layer — in Mapbox Streets v8 they arrive as POIs.

POIs are filtered **by class**, not only by density: `landmark`, `historic`,
`park_like`, `arts_and_entertainment`, `visitor_amenities`. Filtering on `filterrank`
alone surfaced whatever is large and commercial — in a city centre that is a wall of
hotel names, the opposite of what this app is for. `food_and_drink` is off for now;
turn it on when the filter screen exists and the user can ask for it.

House numbers, transit stops and natural-feature names are still off. Add them by
copying the `label-poi` layer onto the `housenum_label`, `transit_stop_label` or
`natural_label` source layers.

Map labels cannot follow the app's Polish/English switch. Mapbox Streets v8 has no
`name_pl` field, so the layers read `name`, the local name, which in Poland is Polish.
English labels would mean publishing a second style that reads `name_en` and choosing
the URL by language — Mapbox bills per user, not per style, so a second one is free.

**Location has four states.** `useUserLocation()` returns `asking`, `denied`,
`unavailable`, or `granted` with coordinates. `denied` and `unavailable` are separate
on purpose: one is the user's choice, the other is a device that produced no fix, and
the screen says something different for each. On the Simulator, `unavailable` is what
you get until you set **Features > Location > Custom Location** — use 50.2649,
19.0238 for Katowice.

## Verification

```bash
npx tsc --noEmit
```

```bash
npx expo export --platform ios --output-dir /tmp/unmapp-export
```

The export proves every import and route resolves, which the type checker does not.
After both pass, look at the screen you changed on the iOS Simulator — there is no
test suite, so seeing it render is the check. A web render does not count: it misses
native text metrics, safe-area insets, and the splash-screen handoff.

`npm run lint` runs `expo lint`, which prompts to install and configure ESLint the
first time it is used — do that before relying on it. There is no test setup yet; see
["Unit Testing with Jest"](https://docs.expo.dev/develop/unit-testing/) when one is needed.
