# AGENTS.md

Map for working in this repo. Keep it short — it points at truth, it is not the truth.

## What this repo is

`unmapp` — an Expo SDK 57 app using expo-router, running on iOS, Android, and web from
one codebase. Currently a starter: `src/app/_layout.tsx` (root Stack) and
`src/app/index.tsx` ("/" screen).

## Hard constraints

- **Expo has changed.** Read the exact versioned docs at
  <https://docs.expo.dev/versions/v57.0.0/> before writing any Expo/React Native code.
  Do not write from memory of older SDKs — APIs, config keys, and package names moved.
  This applies to installed skills too: the `building-native-ui` skill targets SDK 55
  and links v55 docs. Treat its APIs as candidates, not facts — verify each against the
  v57 docs before use.
- **Routes are files.** Anything under `src/app/` is a route. Do not put non-route
  modules there; components, hooks, and helpers go elsewhere under `src/`.
- **Native config lives in `app.json`.** `ios/` and `android/` are generated by
  `npx expo prebuild` and gitignored — never edit or commit them.
- **Imports use the aliases.** `@/*` -> `src/*`, `@/assets/*` -> `assets/*`. No deep
  relative chains (`../../..`).
- TypeScript is `strict`. Do not silence it with `any` or `@ts-ignore`; fix the type.

## Where to look first

| Task | Start here |
| --- | --- |
| Add or change a screen | `src/app/` + [expo-router docs](https://docs.expo.dev/versions/v57.0.0/sdk/router/) |
| App name, scheme, icons, splash, plugins | `app.json` |
| Dependencies / SDK versions | `package.json` (all `expo-*` pinned to `~57.x`) |
| Paths, aliases, TS strictness | `tsconfig.json` |
| Running the app, project layout | [README.md](README.md) |

## Verify changes

```bash
npx tsc --noEmit
```

Then run the app on at least one target (`npm run ios`, `npm run android`, or
`npm run web`) and confirm the screen you touched actually renders. There are no tests
yet, so a manual run is the check.

`npm run lint` (`expo lint`) is not configured yet — the first run installs and sets up
ESLint interactively.

## Keeping docs current

Canonical docs for this repo are [README.md](README.md) and this file. Nothing else —
do not create a `docs/` tree until the repo stops being obvious from these two.

Update them **in the same commit** as the change when it:

- adds, removes, or renames an npm script, or changes how the app is run or built;
- changes the project layout (new top-level directory under `src/`, moved routes,
  new path alias);
- changes `app.json` in a way a contributor must know about (scheme, plugins,
  experiments, new native permissions);
- bumps the Expo SDK — then update the versioned docs URL in this file and in the
  README everywhere it appears;
- invalidates or adds a hard constraint above.

If a change only touches screen internals, no doc update is needed.
